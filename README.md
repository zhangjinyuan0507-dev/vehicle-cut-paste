# 红外车辆拼贴工具 v2 · IR / VIS Vehicle Cut-Paste v2

在航拍背景图上点击摆放车辆，自动生成 **合成图 + VOC XML 标注**。纯前端、无后端、不上传任何数据。

> 本目录是 **v2 新版**，旧版仍在上一层目录（[`../`](../)）。两版可同时打开对照，产出格式相同。

## 两个维度：光谱 × 类别组

顶部三个下拉分别控制 **光谱 / 配色 / 类别组**，各套数据分开存放（**建议各自用不同的输出目录**）：

| 维度 | 取值 | 素材 |
| --- | --- | --- |
| **光谱** | **红外**（灰度素材，融合出灰度）／ **可见光**（彩色素材，融合保留配色） | 红外 90 个 · 可见光 180 个 |
| **配色** | 仅可见光可选：**全部配色**（默认，两套都会被抽到）／ **沙漠迷彩** ／ **军绿** | 每套 90 个 |
| **类别组** | **基础四类**：0 `car1` 装甲车 · 1 `car2` 卡车 · 2 `car3` 轿车 · 3 `car4` 皮卡<br>**类增量新四类**：4 `radar_vehicle` 雷达车 · 5 `military_fuel_tanker` 军用油罐车 · 6 `bridge_layer` 轮式架桥车 · 7 `military_motorcycle` 军用越野摩托车 | 红外 66 + 24 · 可见光 每配色 66 + 24 |

- **素材按需加载**：初始只下载红外基础四类（约 4.6MB）；切到红外类增量、可见光各配色时再分别加载（1.5MB / 5.1MB / 4.4MB），不切就不下载。
- 切光谱/类别组**不会删除已摆放的车**（素材下标全局唯一）：不同套的车会被标为"外来"，在「标注计划」下方给出**黄色警告**（本图/本批各多少辆），并提供「删除本图不属于当前光谱/模式的车」一键清理；保存状态里也会带光谱/类别组标记与混用提示。
- `1-4` 快捷键对应当前**类别组**的四类；类别下拉的编号即上面的官方 ID。

## 标注与融合口径

- **标注框**：标准 VOC —— `(xmin, ymin)` 左上角、`(xmax, ymax)` 右下角，`<depth>1</depth>`；框 = 车辆**实体范围**（素材 alpha 透明边界）在图像上的外接矩形，含旋转后的轴对齐外框，越界裁剪。
- **融合**：把车辆**亮度**重映射到与局部背景一致（对比 = 对比系数 × 背景局部 std；亮度中心 = 背景均值 − (1−亮暗) × 背景 std），并**保留每个像素相对亮度的色彩偏移**。
  - 红外灰度素材偏移恒为 0 ⇒ 结果与旧版按亮度对齐**逐像素一致**（出灰度，实测通道极差 = 0）。
  - 可见光彩色素材 ⇒ 保持自身配色（实测通道极差 ≈ 26），只让明暗贴合背景。
  - 因此**建议红外素材配红外背景、可见光素材配可见光背景**；默认「亮暗 0.8 / 对比 1.0」偏暗调，可见光批次嫌淡可把「对比」提到 1.1~1.3、「亮暗」提到 0.9~1.0。
- **素材预处理**：按 alpha 裁剪 → 等比缩放到「实体最长边 = 画布 × 92%」→ 居中；红外画布 512 转灰度+alpha，**可见光画布 256 保留彩色**（摆放时车一般 30~140px，256 足够，体积小 3 倍）。实体归一化后同一「大小」滑块在各种车型/视角/光谱上含义一致。
- **输出**（与旧版完全一致）：`images/<背景图名>_composite.png`（无框合成图）+ `xml/<背景图名>.xml`（VOC）。

## 怎么用

1. 用 **Chrome / Edge** 打开本页，顶部选好 **光谱 / 配色 / 类别组**。
2. **加载背景图**：把整个文件夹拖进窗口，或点「打开文件夹」选一个目录。
3. **摆放车辆**：点空白处放一辆；点已有车 = 选中并拖动；拖框**四角** = 等比缩放；拖**上方圆点** = 旋转。
4. **指定类别**：按 `1`~`4` 或下拉框（下一辆生效，之后回自动）；不指定则按全图占比自动平衡（目标每类约 25%）。
5. **融合参数**：大小 / 亮暗 / 对比 / 模糊 / 旋转；大小与旋转的调整会成为下一辆的默认值。
6. **删除**：选中后 `Delete` / `Backspace`，或点右下角「框选结果」的 ✕。
7. **保存**：点「选择保存文件夹…」选根目录 → 「保存当前图片 / 保存全部标注」。
8. 快捷键：`1-4` 类别、`z` 撤销、`c` 清空、`s` 保存当前、`←/→` 切图、滚轮缩放、拖空白或右键平移。

## 保存与换目录

- 「保存当前图片」写当前图；「保存全部标注」把所有**待保存**的图一次写完；「**全部重存（含没修改过的）**」把**所有有标注的图**重新合成写一遍（超过 5 张会先确认一次，用于整体重写/换目录后重存）。
- 输出结构固定：`images/<背景图名>_composite.png`（无框合成图）+ `xml/<背景图名>.xml`（VOC）。
- **换保存文件夹不会自动保存**。换目录后，所有**已标注的图（含之前已保存过、没改动过的）都会被标记为「待保存」**，点一次「保存全部标注」就能把它们一起写到新文件夹——适合"存错位置了 / 想同时出一份到别处"的场景。
  - 换目录那一刻不会写任何文件（新目录始终是干净的）；
  - 状态栏会写明"保存文件夹已切到「新目录」：N 张已标注的图都标记为待保存（含没改动过的）…"；
  - 若在系统选择框里点了取消，原目录保持不变、状态也不变。
- 不支持「保存到文件夹」的环境（Firefox / Safari）会逐张下载 `png + xml`，行为一致。

### 保存到错位置了怎么办

**不用重新标注**：输出结构固定（`images/<背景图名>_composite.png` + `xml/<背景图名>.xml`），且 XML 里只写 `<filename>`、**不含输出目录**，所以把文件搬到正确的位置即可，标注含义不变。

- **最简单**：如果整个目录都是错的，直接在资源管理器里把根目录里的 `images/`、`xml/` 两个文件夹**剪切**到正确的根目录（同名冲突时先合并再决定覆盖哪个）。
- **更稳妥**（会先预览、报冲突、可按类别筛选）：

```bat
rem 先预览，不动任何文件
python scripts\move_cutpaste_output.py --from "<错的根目录>" --to "<正确的根目录>"

rem 确认后真移动；只搬指定类别（按 XML 里的 <name>，可用来拆分混在一起的光谱/类别）
python scripts\move_cutpaste_output.py --from "<错的根目录>" --to "<正确的根目录>" --move --only car2,military_fuel_tanker
```

  选项：`--copy`（复制不删源）、`--overwrite`（允许覆盖目标同名文件，默认遇冲突跳过并列出）。
- 避免下次再发生：保存前看一眼右侧「已选择: <文件夹名>」那一行（浏览器出于隐私只暴露文件夹名，不暴露完整路径）；**换保存文件夹前工具会自动把未保存的先写进原目录**，状态栏会写清"写到哪、切到哪"；建议一个批次固定一个输出根目录（基础四类 / 类增量 / 可见光各一个）。

## 背景图载入（大量图片也顺畅）

- **按需解码**：选文件夹/拖文件夹后，工具只登记文件清单（列表立刻可用），真正解码只发生在切到那张图时；内存里最多保留最近 **4 张**解码结果，其余自动释放。因此一次选几百上千张也不会卡死。
- **进度可见**：拖文件夹时显示"已发现 N 个文件"，载入后显示"正在解码：xxx（n/N 张在内存）"，分类组/光谱切换也有加载提示；解码失败的那张会明确提示并可跳过。
- **批量保存**：逐张解码 → 合成 → 写出 → 释放，不会因为图片多而爆内存。
- 单张特别大的图（>4000 万像素）会在状态栏给出提示（合成与保存会变慢）；合成图保持与原图同分辨率。

### 规模上限（实测）

工具侧**没有硬上限**，实测（无头 Chrome，脚本 `scripts/verify_cutpaste_stress.py`，整轮包含浏览器启动 + 载入 4.6MB 素材 + 导航 + 批量保存）：

| 一次载入张数 | 整轮真实耗时 | 内存中解码 | 快速连切 / 批量保存 |
| --- | --- | --- | --- |
| 120 | 1.9 s | 4 张 | 正常 |
| 1,000 | 1.9 s | 4 张 | 正常 |
| 10,000 | 3.2 s | 4 张 | 正常 |
| 20,000 | 约 3~4 s | 4 张 | 正常 |

真正的限制不在工具，而在使用习惯：

1. **选文件本身**：几万个文件时，系统/浏览器的文件夹选择或拖拽收集会明显变慢（这部分由浏览器决定）；
2. **下拉框导航**：超过 1~2 千张后，靠下拉框找图不实用（列表本身不卡）——建议按子文件夹**分批**做；
3. **未保存的标注只在内存**：工具没有持久化，浏览器崩溃或误关页面会丢失未保存的车位。大批量时请**分批 + 勤点「保存全部标注」**（换保存目录后，已标注的图会自动变成待保存，可以一次性整体重存）。

## 注意事项与风险

- 三个包都标注为 **QA 候选**（`qa_only: true`、`approved: false`、`license_allows_training: false`）；可见光包的配色是按厂家可见外观做的程序化首版，**不代表真实型号涂装复刻**，也未经红外辐射标定。投入训练前须完成外观与使用权复核。
- **同一建模的 6 个视角、2 套配色、2 套光谱共享 family**，划分训练/验证/测试时不要拆开（可见光包 README 明确：30 个 blend 是 15 个原车型的材质版本，不能按 30 个独立模型分组）。
- 类别表与旧数据集保持前缀一致（旧类 0~3 不变、新类 4~7 追加）；正式 `data.yaml` 未做任何修改，新类仍属候选。
- **Chrome / Edge** 才能「保存到文件夹」（File System Access API）；Firefox / Safari 会退化为逐张下载。需 HTTPS 或 localhost；直接双击本地 HTML 打开时，部分浏览器会因画布安全限制无法导出图片。
